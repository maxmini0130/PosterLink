# 장애 시 임시 공지 발송 절차

기준일: 2026-08-23

운영 장애, 수집 지연, 로그인/알림/OCR 오류처럼 사용자에게 즉시 알려야 하는 상황에서 임시 공지를 발송하는 절차다. 실제 발송은 `notifications` 테이블에 전체 사용자별 `system_notice` 레코드를 생성하므로, 발송 전 문구와 영향 범위를 반드시 확인한다.

## 사용 경로

1. 관리자 계정으로 `https://www.posterlink.kr/admin`에 로그인한다.
2. 좌측 메뉴에서 `공지 발송`으로 이동한다.
   - 직접 경로: `https://www.posterlink.kr/admin/notifications`
3. `시스템 공지 발송` 영역에서 제목과 내용을 입력한다.
4. `전체 공지 발송` 버튼을 누른다.
5. 브라우저 confirm의 `전체 사용자에게 시스템 공지를 발송할까요?`를 다시 확인한 뒤 승인한다.

발송 API는 `/api/admin/notifications`이고, 관리자 또는 슈퍼관리자만 호출할 수 있다. 서버는 `profiles` 전체 사용자에게 `notifications.type = system_notice`, `target_type = system` 알림을 생성하고 `admin_actions`에 `system_notice_broadcast` 이력을 남긴다.

## 사용자 노출 위치

- 로그인 사용자 헤더의 알림 아이콘에 읽지 않은 알림 배지가 표시된다.
- `/notifications` 화면에 공지 제목과 본문이 표시된다.
- 현재 시스템 공지는 앱 내 알림 레코드만 생성한다. Expo push 발송이나 비로그인 홈 배너 노출은 포함하지 않는다.

## 발송 전 체크

- 장애가 실제 사용자에게 영향을 주는지 확인한다.
- 장애 범위가 일부 기능이면 전체 서비스 장애처럼 표현하지 않는다.
- 복구 예상 시간이 불확실하면 구체 시각을 단정하지 않는다.
- 개인정보, 내부 URL, secret, 운영자 개인 연락처를 본문에 넣지 않는다.
- 같은 장애에 대한 중복 발송을 피하기 위해 `/admin/notifications`의 최근 시스템 공지를 먼저 확인한다.

## 권장 문구

### 서비스 일부 기능 장애

제목:

```text
일부 기능 이용 지연 안내
```

본문:

```text
현재 일부 기능 이용이 일시적으로 지연되고 있습니다.
공고 열람은 가능하지만 검색, 알림, 이미지 처리 중 일부 동작이 늦어질 수 있습니다.
복구가 완료되면 다시 안내드리겠습니다.
```

### 로그인/OAuth 장애

제목:

```text
로그인 이용 지연 안내
```

본문:

```text
현재 일부 로그인 방식에서 접속이 지연되고 있습니다.
이미 로그인된 사용자는 기존 기능을 계속 이용할 수 있으며, 복구가 완료되면 다시 안내드리겠습니다.
```

### 복구 완료

제목:

```text
서비스 이용 정상화 안내
```

본문:

```text
일시적으로 지연되던 기능이 정상화되었습니다.
이용에 불편을 드려 죄송합니다. 같은 문제가 반복되면 고객 문의 채널로 알려주세요.
```

## 발송 후 확인

1. `/admin/notifications`의 `최근 시스템 공지`에 발송 이력이 표시되는지 확인한다.
2. 수신자 수가 예상 사용자 수와 크게 다르지 않은지 확인한다.
3. 일반 사용자 계정으로 로그인해 헤더 알림 배지와 `/notifications` 목록 노출을 확인한다.
4. 필요하면 Supabase `notifications`에서 동일 제목의 생성 시각과 건수를 확인한다.
5. 장애가 복구되면 복구 완료 공지를 별도로 발송한다.

## 주의 사항

- 발송 취소 기능은 현재 없다. 잘못 보낸 경우 정정 공지를 다시 발송한다.
- 운영 DB에서 알림을 직접 삭제하는 작업은 대량 삭제에 해당하므로 별도 승인을 받은 뒤 수행한다.
- 시스템 공지는 로그인 사용자에게만 보인다. 비로그인 사용자에게도 알려야 하는 장애는 별도 홈 배너 또는 Vercel 공지 페이지가 필요하다.
- 모바일 푸시까지 보내야 하는 긴급 장애 공지는 현재 시스템 공지 기능만으로는 부족하다. 별도 push broadcast 기능을 추가해야 한다.
