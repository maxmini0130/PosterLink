# PosterLink 기능 가이드 및 개선 과제

기준일: 2026-08-24

## 1. 서비스 목적

PosterLink는 정부, 지자체, 공공기관, 공익기관의 지원사업, 교육, 행사, 채용, 모집 공고를 모아 사용자가 빠르게 발견하고 공식 신청 경로로 이동할 수 있게 돕는 서비스다.

핵심 원칙은 다음과 같다.

- 실제 주관기관, 게시 출처, 신청 기관을 구분한다.
- 원문 상세 URL과 신청 URL을 구분한다.
- 신청기간이 불확실한 공고를 임의로 상시모집처럼 보이지 않게 한다.
- 실제 포스터가 아닌 로고, 배너, 지도, 장식 이미지를 대표 포스터로 쓰지 않는다.
- 공개 화면에는 사용자에게 필요한 신뢰 정보만 보여주고, 내부 검수 상태는 노출하지 않는다.

## 2. 공개 사용자 기능

### 홈

- 오늘 새 공고, 신청 가능한 공고, 이번 주 마감 공고, 수집 중인 기관 수를 요약한다.
- 신청 가능한 공고만 보는 토글을 제공한다.
- 마감 임박, 새로 등록, 많이 본 공고 탭을 제공한다.
- 카테고리, 지역, 기관 바로가기를 제공한다.
- 초기 서버 HTML에 서비스 제목과 검색 진입 링크가 포함되어 검색엔진과 공유 미리보기에 기본 정보가 잡힌다.

### 공고 찾기

- `/posters`에서 키워드 검색, 카테고리 필터, 지역 필터, 정렬을 제공한다.
- 정렬은 최신순, 마감순, 인기순, 조회순, 찜순 기준을 지원한다.
- “접수 중인 공고만 보기”는 아래 기준을 사용한다.
  - 시작일이 없거나 이미 시작한 공고
  - 마감일이 현재 이후인 공고
  - 마감일이 없더라도 `ongoing`, `until_exhausted`처럼 명시적으로 열린 모집 유형인 공고
  - 마감일 없음, 시작일만 있음, 날짜 오류, 아직 시작 전 공고는 접수 중으로 보지 않는다.
- 검색어 제출 시 검색 로그를 기록해 관리자 인기 검색어 집계에 반영한다.
- 의미 기반 검색 API가 가능하면 semantic search를 사용하고, 아니면 일반 검색 RPC로 대체한다.

### 공고 카드

- 제목, 기관명, 지역/카테고리 태그, 대표 이미지, 마감 상태, 주요 지표를 보여준다.
- 마감 상태는 공통 계산 로직을 사용한다.
  - 오늘 마감
  - 마감 임박
  - 신청 가능
  - 신청 예정
  - 신청 마감
  - 기관 공고 확인
  - 상시 또는 소진 시까지
- 마감된 공고는 카드에서 흐리게 보여 사용자가 진행 중 공고와 구분할 수 있다.

### 공고 상세

- 포스터 이미지, 제목, 요약, 상세 설명, 신청기간, 기관 정보, 지역/카테고리, 공식 링크를 제공한다.
- 공식 공고 URL, 신청 URL, 참고 URL은 목적별로 분리해 관리한다.
- 공개 화면에는 내부 `verification_status`, 검수 대기, 반려 같은 운영용 상태를 노출하지 않는다.
- 검증 완료 공고는 확인 시각을 보여주고, 그렇지 않은 공고는 공식 공고 확인을 권장하는 공개 문구를 보여준다.
- 조회수, 공식 링크 클릭, 찜 같은 사용자 행동 지표를 기록한다.

### 지역/카테고리/기관 랜딩

- `/regions/[region]`
- `/categories/[category]`
- `/regions/[region]/[category]`
- `/institutions`
- `/institutions/[slug]`

위 경로는 공개 탐색과 SEO 유입을 위한 랜딩 페이지다.

기관 상세에서는 다음을 구분한다.

- 해당 기관이 실제 주관 또는 주최하는 공고
- 해당 기관 채널에서 게시 또는 수집된 공고
- 현재 신청 가능한 공고 수
- 공식 홈페이지와 기관 인증 상태

### 회원 기능

- 이메일 로그인과 OAuth 로그인을 지원한다.
- 사용자 프로필에서 관심 지역과 관심 카테고리를 설정한다.
- 찜한 공고를 저장하고 마이페이지 또는 찜 목록에서 다시 볼 수 있다.
- 기관 팔로우를 통해 관심 기관을 저장할 수 있다.
- 알림 화면에서 시스템 알림, 마감 알림, 관심 조건 관련 알림을 확인하는 구조를 갖고 있다.

## 3. 운영자 기능

### 공고 등록 및 편집

- 운영자는 포스터 이미지나 공고 자료를 업로드하고 공고 초안을 만든다.
- OCR과 구조화 도구를 통해 제목, 기관, 기간, 요약, 링크, 지역, 카테고리 후보를 추출한다.
- 신청 시작일, 신청 마감일, 마감 유형을 구조화한다.
- 공식 링크와 참고 링크를 분리한다.
- 미리보기 후 검수 요청 또는 게시 상태로 전환한다.

### 검수 대기 후보 관리

- 크롤러나 운영자가 수집한 후보 공고를 검수한다.
- 실제 포스터 기준에 맞지 않는 텍스트 공고, 채용 공고, 안내문 등은 포스터로 자동 승인하지 않는다.
- 공중화장실 관리인 모집처럼 포스터 기준에 맞지 않는 자료는 별도 텍스트 공고 후보 정책으로 판단한다.
- AI 신뢰도가 낮거나 근거가 부족한 항목은 자동 승인하지 않고 사람 검수로 보낸다.

### 크롤러 운영

- 수집 출처를 관리한다.
- 수집 실행 이력과 최근 수집 결과를 확인한다.
- 원문 URL, 첨부파일, OCR 근거, 추출 근거를 보존한다.
- 운영 DB 대량 쓰기나 정리는 명시적 승인 후에만 수행한다.

## 4. 관리자 기능

### 관리자 대시보드

- 검수 대기 공고, 게시 상태 공고, 신고 대기, 가입 사용자, 공식 링크 클릭 수를 요약한다.
- 인기 검색어와 최근 관리자 작업 로그를 확인한다.

### 공고 관리

- 공고 목록 검색, 필터, 정렬, 상태 변경, 수정, 반려, 삭제를 지원한다.
- 관리자 미리보기에서 공개 카드와 상세 표시를 확인할 수 있다.
- 구조화된 날짜와 검수 체크리스트를 함께 관리한다.

### 사용자/신고/설정 관리

- 사용자 목록과 역할을 확인한다.
- 댓글 또는 사용자 신고를 처리한다.
- 카테고리, 지역, 기관, 운영 기준 데이터 관리 화면을 제공한다.
- 공지 발송과 운영 로그 확인 구조가 있다.

## 5. 데이터 및 신뢰성 기능

- Supabase Auth, PostgreSQL, Storage, Edge Functions 기반이다.
- RLS와 역할 경계를 유지한다.
- 공개 사용자는 공개 공고만 조회한다.
- 운영자/관리자 기능은 역할에 따라 분리된다.
- 서비스 역할 키는 서버 전용 작업에만 사용하고 클라이언트 번들에 노출하지 않는다.
- 검색 로그, 공식 링크 클릭 로그, 조회 로그, 관리자 작업 로그를 수집한다.
- 구조화된 날짜가 검증되지 않은 경우 SEO 이벤트나 캘린더 신뢰 데이터로 사용하지 않는다.

## 6. SEO 및 공개 노출

- `robots.txt`, `sitemap.xml`, Open Graph 이미지 경로를 제공한다.
- 사이트맵에는 홈, 공고 목록, 공고 상세, 지역, 카테고리, 지역-카테고리, 기관 목록, 기관 상세, 약관/개인정보처리방침이 포함된다.
- 공개 상세와 랜딩 페이지는 canonical metadata와 structured data를 사용한다.
- 홈 초기 HTML에는 핵심 소개 문구와 탐색 링크가 포함된다.

## 7. 모바일 앱

- Expo 기반 모바일 앱이 있다.
- Android Google Play 출시 준비 흐름이 진행 중이다.
- 앱은 웹 서비스를 WebView로 감싸고, 하단 주요 액션과 인증 흐름을 모바일 환경에 맞춘다.
- Google Play Console 개발자 계정 인증과 연락처 인증이 완료되어야 앱 생성 및 제출을 진행할 수 있다.

## 8. 앞으로 개선할 부분

### 출시 전 P0

- 운영 DB에 `search_public_posters`, `match_posters_by_embedding` 날짜 필터 보정 마이그레이션을 승인 후 적용해야 한다.
- 적용 후 `/posters`, semantic search, sitemap, 홈 요약의 신청 가능 수가 운영 DB 기준으로 일관되는지 실제 운영 데이터로 재확인해야 한다.
- 검수 대기 중인 후보 중 실제 포스터가 아닌 텍스트 공고를 자동 포스터로 노출하지 않는 운영 기준을 계속 보강해야 한다.

### 출시 전 P1

- Google Play Console 개발자 계정 신원 확인과 연락처 전화번호 인증을 완료해야 한다.
- Android 실제 기기에서 로그인, OAuth callback, 카메라/파일 권한, 알림 토큰 저장을 검증해야 한다.
- iOS 제출용 App Store Connect API 권한과 빌드 제출 흐름을 정리해야 한다.
- Kakao admin key 사용 여부를 결정해야 한다. 앱 연결 해제나 운영자 강제 정리 기능이 필요할 때만 쓴다.
- 관리자 수동 검수 승인 기준을 문서화하고, 사람 검수 완료 전 자동 공개되지 않게 운영 절차를 고정해야 한다.

### 품질 개선

- 검색 결과 없음, 마감 정보 없음, 기관 정보 부족 같은 빈 상태 문구를 더 친절하게 정리한다.
- 관리자 지표 라벨을 “누적”, “현재 신청 가능”, “검수 대기”처럼 계산 기준이 드러나게 계속 통일한다.
- 공개 랜딩 페이지의 지역/카테고리 조합 우선순위를 실제 검색 수요와 공고 수 기준으로 조정한다.
- 인기 검색어가 충분히 쌓이지 않은 초기에는 기본 추천 검색어와 실제 인기 검색어를 구분해 보여준다.
- AI 추출 신뢰도, OCR 원문 근거, 사람 검수 완료 여부를 운영자가 더 빠르게 비교할 수 있는 검수 화면을 강화한다.

### 운영 개선

- 운영 DB 보안 hardening migration은 승인 후 단계적으로 적용하고, 적용 전후 Supabase Advisor를 재확인한다.
- Edge Function 로그, 크롤러 실패 로그, OCR 실패 로그를 정기 점검한다.
- 출시 후 24시간 동안 회원가입, 로그인, 공고 상세 404, 공식 링크 클릭, 신고/댓글 남용 여부를 모니터링한다.
- DNS 연결은 `posterlink.kr`, `www.posterlink.kr` 우선으로 확인하고, `posterlink.co.kr`은 별도 결정 후 진행한다.
