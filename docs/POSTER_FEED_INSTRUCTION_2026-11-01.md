## 작업 순서

### 1. 먼저 조사만 하고 보고 (코드 수정 전)

- 공고 중 이미지 상태 분포: 원본 있음 / 없음 / 부적합(가로·세로 400px 미만, 가로/세로 > 1.9, 로고·아이콘) / 불러오기 실패 — 출처별 건수와 비율
- 현재 이미지 저장·제공 방식(원본 외부 URL 직접 사용인지, Supabase Storage 사본인지), Next.js `next/image` 사용 여부와 `remotePatterns` 설정
- 이미지 가로·세로 크기를 이미 저장하는 컬럼이 있는지

### 2. 기본 이미지 (DefaultPoster)

- 분야 8색·아이콘·제목(명조, 최대 5줄)·기관명·PosterLink 표기로 3:4 이미지를 그리는 컴포넌트. 색과 구성은 `DefaultPoster` 시안 그대로
- 같은 디자인을 서버에서 이미지로도 만들 수 있게(`next/og` 등) 해서 og:image와 목록 썸네일에 공용
- 화면에서 원본 불러오기 실패 시(onerror) 즉시 기본 이미지로 교체
- 결과: 홈·찾기·내 공고 어디에도 이미지 없는 카드가 없어야 함

### 3. 이미지 메타데이터와 판정

- 공고 이미지에 `image_width`, `image_height`, `image_status`(ok / missing / unsuitable / broken) 저장하는 마이그레이션 **파일만 작성**(로컬 적용, 운영 적용 금지)
- 판정 스크립트는 로컬·스테이징에서 dry-run → 건수 리포트. 운영 백필은 승인 후
- 앞으로 수집되는 공고는 수집 단계에서 판정

### 4. 홈 포스터 피드 (FeedCard)

- 3-4장 C항 그대로: 3:4 틀, **contain**(잘라 채우기 금지), 남는 곳 #ECE7DA, 세로/가로 > 2.0은 윗부분 + '전체 보기'
- 포스터 위 상태 배지(왼쪽 위)·찜 버튼(오른쪽 위, 44px 터치, aria-pressed), 아래 제목 2줄 + '대상 지역 · 기관명'
- 모바일 2열 / 768~1199px 3열 / 1200px 이상 4열, 오른쪽 보조 열 제거
- 상단: 로고 · 지역(조건) 칩 · 검색 → 보기 탭(회원 `새 공고 N · 7일 안에 마감 N · 전체`, 비회원 `지금 접수 중 · 7일 안에 마감`). 큰 제목·안내 상자 제거
- 첫 방문에 관심 조건 화면 자동 표시 제거. 비회원은 4번째 카드 뒤 관심 분야 안내 카드 1회(닫으면 7일간 숨김)
- 정렬 규칙은 기존 유지, 같은 점수 구간에서 실제 포스터 우선 + 기본 이미지 3장 연속 금지
- '방문 이후' 문구는 회원·관심 조건 있을 때만. 카드에 수집 출처명 금지(기관명 없으면 대상 지역만)
- 헤더의 로그인/회원가입 버튼은 `로그인` 하나로 통합(카카오·네이버 선택은 로그인 화면에서)

### 5. 성능

- 목록 이미지는 변환본(폭 360·540·720px, WebP/AVIF)만 요청. 저장된 가로·세로로 틀을 먼저 그려 CLS 0.1 이하
- 첫 줄 2~4장만 우선 불러오기, 나머지 지연 불러오기
- 외부 원본을 직접 핫링크하고 있다면 그 사실과 대안(저장소 사본+변환)을 보고만 하고, 대량 다운로드는 승인 후
