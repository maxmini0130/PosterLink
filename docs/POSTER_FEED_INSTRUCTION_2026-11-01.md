# 홈 포스터 피드 전환 — 개발 지시 (2026-11-01)

대상: 로컬 개발 서버(localhost:4000). 기준 문서: `docs/UI_REDESIGN_PLAN_2026-10-31.md` 3-4장 **C항 「홈 — 포스터 피드」**(이전 C·D 대체), 시안 `docs/design/posterlink-mobile-v3/` 의 `FeedFirst` · `FeedHome` · `PcFeed` · `DefaultPoster`.

## 지킬 것 (변경 없음)
- 운영 DB 쓰기·마이그레이션 적용·배포·push 금지 (승인 후 진행)
- Preview도 운영 DB에 연결되어 있으므로 Preview에서 쓰기 동작 테스트 금지
- deny 규칙: git push, vercel --prod, vercel deploy --prod, supabase db push, 운영 DB에 쓰는 SQL 실행
- 백필은 승인 전 금지(로컬·스테이징에서만)
- 분석 이벤트에 검색어 원문·이메일·전화번호·토큰을 보내지 않음

## 작업 순서

### 1. 먼저 조사만 하고 보고 (코드 수정 전)
- 공고 중 이미지 상태 분포: 원본 있음 / 없음 / 부적합(가로·세로 400px 미만, 가로/세로 > 1.9, 로고·아이콘) / 불러오기 실패 — 출처별 건수와 비율
- 현재 이미지 저장·제공 방식(원본 외부 URL 직접 사용인지, Supabase Storage 사본인지), Next.js `next/image` 사용 여부와 `remotePatterns` 설정
- 이미지 가로·세로 크기를 이미 저장하는 컬럼이 있는지

### 2. 기본 이미지 (DefaultPoster)
- 분야 8색·아이콘·제목(명조, 최대 5줄)·기관명·PosterLink 표기로 3:4 이미지를 그리는 컴포넌트. 색과 구성은 `DefaultPoster` 시안 그대로
- 같은 디자인을 서버에서 이미지로도 만들 수 있게(`next/og` 등) 해서 og:image와 목록 썸네일에 공용
- 화면에서 원본 불러오기 실패 시(onerror) 즉시 기본 이미지로 교체
- 결과: 홈·찾기·내 공고 어디에도 이미지 없는 카드가 없어야 함

### 3. 이미지 메타데이터와 판정
- 공고 이미지에 `image_width`, `image_height`, `image_status`(ok / missing / unsuitable / broken) 저장하는 마이그레이션 **파일만 작성**(로컬 적용, 운영 적용 금지)
- 판정 스크립트는 로컬·스테이징에서 dry-run → 건수 리포트. 운영 백필은 승인 후
- 앞으로 수집되는 공고는 수집 단계에서 판정

### 4. 홈 포스터 피드 (FeedCard)
- 3-4장 C항 그대로: 3:4 틀, **contain**(잘라 채우기 금지), 남는 곳 #ECE7DA, 세로/가로 > 2.0은 윗부분 + '전체 보기'
- 포스터 위 상태 배지(왼쪽 위)·찜 버튼(오른쪽 위, 44px 터치, aria-pressed), 아래 제목 2줄 + '대상 지역 · 기관명'
- 모바일 2열 / 768~1199px 3열 / 1200px 이상 4열, 오른쪽 보조 열 제거
- 상단: 로고 · 지역(조건) 칩 · 검색 → 보기 탭(회원 `새 공고 N · 7일 안에 마감 N · 전체`, 비회원 `지금 접수 중 · 7일 안에 마감`). 큰 제목·안내 상자 제거
- 첫 방문에 관심 조건 화면 자동 표시 제거. 비회원은 4번째 카드 뒤 관심 분야 안내 카드 1회(닫으면 7일간 숨김)
- 정렬 규칙은 기존 유지, 같은 점수 구간에서 실제 포스터 우선 + 기본 이미지 3장 연속 금지
- '방문 이후' 문구는 회원·관심 조건 있을 때만. 카드에 수집 출처명 금지(기관명 없으면 대상 지역만)
- 헤더의 로그인/회원가입 버튼은 `로그인` 하나로 통합(카카오·네이버 선택은 로그인 화면에서)

### 5. 성능
- 목록 이미지는 변환본(폭 360·540·720px, WebP/AVIF)만 요청. 저장된 가로·세로로 틀을 먼저 그려 CLS 0.1 이하
- 첫 줄 2~4장만 우선 불러오기, 나머지 지연 불러오기
- 외부 원본을 직접 핫링크하고 있다면 그 사실과 대안(저장소 사본+변환)을 보고만 하고, 대량 다운로드는 승인 후

## 보고 형식
1. 1번 조사 결과(출처별 이미지 상태 표)
2. 변경 파일 목록과 커밋 해시(로컬 브랜치, push 금지)
3. 스크린샷: 360 · 390 · 430 · 768 · 1280 · 1440px 홈, 기본 이미지가 섞인 화면, 가로 배너·아주 긴 이미지 카드
4. UI 문서 6장 3단계 체크리스트 결과
5. 하지 않은 것과 승인이 필요한 것(마이그레이션 운영 적용, 백필, 이미지 사본 저장)

## 추가 지시 (2026-11-03) — 카드 정보·지역 문구·기관 팔로우·측정

기준: UI 문서 3-4장 C항의 「포스터 카드」 표, 「지역 문구」, 「기관 팔로우 제안」, 「첫 공략 대상과 기본 피드」, 재방문 지시서 0-2 이벤트 표와 0-5 지표. 시안 `FeedFirst`·`FeedHome`·`PcFeed`·`FollowPrompt`.

### 6. 먼저 조사하고 보고 (수정 전)
- 공고에 **실제 모집 기관(organizer)**과 **수집 출처(source)**가 따로 저장되는지. 섞여 있다면 출처별로 organizer를 채울 수 있는 비율(원문에서 추출 가능한지)
- 지역 데이터가 장소(venue) / 신청 자격 지역 / 기관 소재지로 구분돼 있는지, 각 값이 채워진 비율
- 신청 대상, 혜택(무료·금액·체험) 정보를 원문에서 뽑을 수 있는 비율(출처별 표본 20건씩)
- 기존 기관 팔로우(구독) 기능의 테이블·화면·대상 id가 organizer인지 source인지

### 7. 카드 정보
- 카드 아래를 제목 2줄 / `지역 문구 · 신청 대상` / 핵심 정보 1개로 구성. 확인 안 된 값은 줄째 생략
- `benefit_summary`(20자 이내) 필드 추가 마이그레이션 **파일만**, 추출은 로컬·스테이징 dry-run과 검수 대기열 연결까지
- 지역 문구는 장소=`○○에서`, 자격 확인=`○○ 주민`, 연관만=`○○ 관련`, 서울 전체/전국

### 8. 상단 조건 표시와 기본 피드
- 상단에 실제 적용 조건을 글로(`마포구 · 교육/취업 · 문화/행사` + `변경`). 조건 없으면 `서울 전체` 또는 `전체 지역`
- 조건 없는 첫 방문 기본 피드: 서울 관련 접수 중 공고, 최신 등록 중심

### 9. 기관 팔로우 제안
- 화면 표기 `팔로우`로 통일. 대상은 organizer만, organizer 없는 공고에는 제안 안 함
- 찜 직후 또는 상세 20초 체류·끝까지 스크롤 후, 한 방문 최대 1회. 팔로우·거절 기관 재제안 금지
- 비회원은 기존 return_to + `pending_action: follow` 흐름으로 가입 후 자동 팔로우
- 문구는 현재 기능(홈 '팔로우 기관 소식')만. 알림 약속 문구 금지

### 10. 측정
- 이벤트 추가: `follow_prompt_shown/click/dismiss`(prompt_id), `institution_follow`에 prompt_id, `signup_start`에 prompt_id, `outbound_apply_click`에 버튼 유형, `feed_card_impression`
- 기존 이벤트와 중복 생성 금지 — 이미 있는 것은 속성만 추가
- 주간 콘텐츠 공급 지표 쿼리 4종(재방문 지시서 0-5) 작성, 로컬·스테이징 데이터로 1회 실행 결과 첨부

### 보고 추가
- 6번 조사표, 카드 세 줄이 적용된 390px·1280px 스크린샷, 팔로우 제안 흐름(회원·비회원) 스크린샷, 콘텐츠 공급 지표 1회 결과

## 추가 지시 2 (2026-11-03 오후) — 홈 구성 v5

기준: UI 문서 3-4장 **C-0 「홈 구성 v5」**, 시안 `HomeV5`(모바일)·`PcHomeV5`(PC). 기존 홈의 탭과 피드 중간 관심 분야 안내 카드는 제거.

### 11. 홈 섹션
- 순서: 지역 칩+검색+한 줄 소개·규모 → 분야 바로가기 8개 → 이번 주 눈여겨볼 공고 → 7일 안에 마감 → 새로 올라온 공고(12장 + 자동 이어 불러오기) → 12장마다 자동 기획 묶음 → 팔로우할 만한 기관(1회)
- 모바일 가로 줄(카드 폭 150px), PC 4열. 카드 컴포넌트는 기존 FeedCard 재사용(배율만 다름)
- 홈 전체 중복 금지(위 섹션 우선), 3개 미만 섹션 숨김
- 홈 데이터는 한 번의 서버 요청(또는 섹션별 병렬)으로, 첫 화면 섹션은 서버 렌더링

### 12. 눈여겨볼 공고 선정
- 공고에 `featured_week`(선정 주) 저장 — 마이그레이션 **파일만**. 관리자 공고 화면에 "이번 주 선정" 토글(로컬)
- 선정 부족 시 자동 채움: 접수 중 + benefit_summary 있음 + 최근 7일 찜·조회 상위

### 13. 자동 기획 묶음
- 이번 주말 무료 체험(진행일 이번 토·일 + 무료), 청년 지원금·월세 모음, 이번 주 새 공고를 올린 기관. 조건 쿼리를 함수로 분리해 나중에 묶음을 추가하기 쉽게
- 진행일(`event_start_date`)이 없거나 지난 공고는 주말 묶음·홈에서 제외. 진행일 필드 유무와 채움 비율을 6번 조사에 함께 보고

### 14. 이어 불러오기와 측정
- 화면 끝 600px 전에 다음 12장, `더 보기` 링크(URL 페이지 번호) 병행, 뒤로 가기 시 위치 복원
- `feed_card_impression`과 카드 클릭에 `section_id` 추가

### 보고 추가
- 모바일 390px·PC 1280px 홈 전체 스크린샷(섹션 모두 보이게), 섹션별 실제 공고 수, 숨겨진 섹션과 이유
