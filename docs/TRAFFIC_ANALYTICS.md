# 자체 방문 통계 기준

적용 대상: `/admin/traffic`, `/api/admin/traffic`, `SiteVisitTracker`, `site_visit_logs`.
GA4 및 Vercel 통계와는 수집·식별·동의·제외 기준이 다르므로 수치를 합산하지 않는다.

## 지표 계약

| 항목      | 기준                                                                                | 해석상 한계                                                                                |
| --------- | ----------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| 기간      | Asia/Seoul 자정부터 현재. 최근 N일은 오늘 포함                                      | 수집 시각은 UTC로 보존, 화면은 한국 시간                                                   |
| 방문자    | 각 기록에서 계정 ID → IP HMAC 해시 → 브라우저 visitor_key 순으로 선택하여 중복 제거 | 실인원 아님. 공유 IP는 합쳐지고, 로그인 전후·네트워크 변경은 나뉠 수 있음                  |
| 세션      | sessionStorage의 session_key. 없으면 방문자 식별자로 대체                           | 탭 수명 기준. 30분 비활동이나 자정에 자동 갱신하지 않음. 복제 탭은 식별자를 공유할 수 있음 |
| 페이지뷰  | 수집된 공개 경로·허용 쿼리 조합의 이동 기록                                         | 같은 렌더의 중복 효과는 방지. 새로고침은 새 기록. 모든 HTTP 요청·체류·고유 사람 수가 아님  |
| 유입·랜딩 | 선택 기간에서 관측된 세션의 가장 오래된 포함 기록                                   | 기간 이전 첫 접속이나 제외된 기록은 소급 조회하지 않음                                     |
| 누적      | 보관된 로그의 전체 기간                                                             | 서비스 개설 이후 실제 이용자 전체라고 단정하지 않음                                        |

출처별 세션은 하나의 출처에 배정한다. 방문자는 서로 다른 세션에서 다른 출처에
나타날 수 있으므로 출처별 방문자 합계는 전체 방문자와 같지 않을 수 있다.
로그인 전후에도 같은 탭의 세션 식별자는 유지될 수 있다.

## 출처 판정

1. 기존 저장 기록에 유효한 `utm_source`가 있으면 우선 사용한다.
2. 자체 도메인의 referrer는 **사이트 내부 이동**이다. 신규 외부 유입의 증거가 아니다.
3. referrer가 없으면 **출처 미확인**이다. 주소 입력, 즐겨찾기, 공유 앱,
   브라우저 제한, 개인정보 필터, 과거 미수집을 구분할 수 없다.
4. 외부 referrer는 도메인 경계를 확인해 Google/Naver 등으로 표시한다.
   `google.com.evil.test`를 Google로 분류하지 않는다.

`document.referrer`는 문서가 열린 출처이며 SPA 이동마다 갱신되는 값이 아니다.
최근 로그의 유입은 해당 기록의 referrer 분류, 유입 경로 차트는 기간 내 세션 첫 기록의
분류다. 내부 이동·미확인을 Google 등으로 임의 보정하거나 주소 입력으로 추정하지 않는다.

개인정보 정책 보존: 원문 referrer URL·쿼리를 저장하지 않고 기존 `safeReferrer`의
허용된 공개 출처 origin만 보존한다. 허용 목록 밖의 출처는 미확인으로 남는다.
자체 로그의 UTM은 `sanitizedVisitQuery`가 제거하며 신규 계정·캠페인 연결 수집을
활성화하지 않는다. 화면의 UTM은 과거 저장값을 위한 호환 표시다.

## 기본 제외와 테스트 절차

- 확인된 관리자·최고 관리자·운영자, `is_automated`, 자동화 출처 표시,
  WebDriver, 봇·자동화 User-Agent 신호를 기본 제외한다.
- 단순 반복 방문, Mac/Windows 여부, 방문 시각만으로 테스트나 봇으로 확정하지 않는다.
- 로그인 전 수동 테스트는 계정 역할로 제외할 수 없다. 테스트 전 관리자 화면에서
  **이 브라우저 테스트 방문 제외**를 켠다. 이후 수집은 기존 `automation_source`에
  `manual-test`를 기록하여 기본 집계에서 제외하며, 내역에는 **내부 수동 테스트**로 표시한다.
- 표시는 해당 origin의 localStorage에만 저장된다. 로그아웃·탭 재개에도 유지되며,
  다른 기기·브라우저·www 여부가 다른 주소에는 별도 설정해야 한다.
  이미 열린 탭은 새로고침한다. 브라우저 저장소 삭제 시 해제된다.
- 끄면 이후 수집에 적용한다. 과거 테스트 기록은 재포함하거나 삭제하지 않는다.
  별도의 `_pl_automation` 세션 표시가 있으면 브라우저 테스트 표시를 꺼도 그것은 유지된다.
- 자동 검증은 `_pl_automation=codex-ai-review` 또는 E2E 표시를 사용한다.
  정책상 DB 쓰기가 허용되지 않은 검증은 방문 API 전송 자체를 차단한다.
- **내부·자동 방문 포함**은 검사용 보기 전환이며 테스트 브라우저 설정과 별개다.

이 표시는 권한 부여 기능이 아니다. 일반적인 UA를 사용하는 위장 봇과 표시 없는
비로그인 테스트를 전부 판별할 수 없으므로 화면은 사람 수를 보장하지 않는다.
수동 테스트도 기존 자동화 제외 필드를 재사용하되 라벨로 구분한다.

## 완전성·운영

- 상세 차트·로그는 기간 내 최신 10,000건 한도다. 한도 도달 시 화면에 경고한다.
  제외 건수도 조회된 범위의 기록 수이며 전체 누적 제외 건수가 아니다.
- RPC 누적 요약과 상세 조회는 시점과 한도가 달라 값이 다를 수 있다.
  RPC 미지원 시 최근 로그로 대체하고 `overviewExact=false`를 표시한다.
  대체 조회나 권한 조회 실패를 방문 0건으로 성공 처리하지 않는다.
- 마지막 갱신은 통계 응답 생성 시각이며 마지막 사용자 방문 시각과 다르다.
  갱신 실패 시 오류와 기존 갱신 시각을 확인한다. API는 동적 응답을 사용한다.
- 원본·과거 로그는 삭제하지 않는다. 이번 변경은 스키마·RLS·운영 DB 변경이 없다.
  과거의 미확인 방문은 새로운 근거 없이 테스트로 소급 제외하지 않는다.
- 배포 전: 관련 회귀 테스트, 웹 lint/build, 격리된 모바일·데스크톱 UI 검증.
  운영에서 테스트 브라우저 표시를 켠 다음 비로그인 접속의 제외를 확인한다.
  운영 검증을 위한 쓰기나 DB 마이그레이션은 별도 명시 승인 범위에서만 수행한다.

pnpm --filter web build
