# PosterLink v6.1 구현 명세

이 문서는 코드 작업 도구(Claude Code, Codex)가 읽고 구현하도록 쓴 명세입니다. 디자인 검토에서 합의한 내용을 옮겼고, 합의되지 않아 권장안으로 채운 곳은 12장에 모았습니다.

## 0. 읽는 법

- **우선순위**: 이 문서의 규칙 > `reference/`(치수·색·문구) > `screens/`(실제 포스터가 들어간 모습). 서로 다르면 앞의 것을 따릅니다.
- **이름은 제안입니다.** 이 문서의 필드·함수 이름은 뜻을 전하려는 것입니다. 저장소의 기존 이름과 관례에 맞추세요. 지켜야 하는 것은 입력과 화면 결과입니다.
- **코드는 보지 못하고 썼습니다.** 1.3절은 실행 중인 화면을 조작해 확인한 내용입니다. 작업 전에 코드에서 다시 확인하세요.
- **날짜 예시는 2026-11-09(월), 서울 시각 기준**입니다.
- **모르는 것은 추측하지 말고 물어보세요.** 12장의 '정할 것'은 답을 받기 전까지 권장안으로 구현하되, 한 곳만 바꾸면 뒤집을 수 있게 만드세요.
- 10장의 단계 순서대로 진행하고, 한 단계가 끝날 때마다 완료 기준을 확인한 결과를 보고하세요.

## 1. 목표와 범위

### 1.1 무엇을 만드는가

공공기관 포스터·공고를 모아 보여주는 PosterLink의 홈, 상세, 찜 화면을 새 디자인(v6.1)으로 바꿉니다. 핵심은 세 가지입니다.

1. **마감을 확인된 만큼만 보여준다.** 잘못된 마감일은 이용자가 신청 기회를 놓치게 합니다(4장).
2. **신청한 공고를 표시할 수 있다.** 표시하면 마감 안내에서 빠지고 찜의 '신청한 공고'에 모입니다(5장).
3. **포스터가 먼저 보이고, 카드만 보고도 내가 신청할 수 있는지 판단할 수 있다**(6·7장).

기준 구현은 **Home v5(로컬에서 4021 포트로 띄우던 쪽)** 입니다. 모바일 첫 화면은 포스터가 빨리 보이도록 상단을 줄입니다.

### 1.2 범위

**범위 안**
- 마감 표시 규칙과 그에 필요한 데이터 항목
- 공고 카드, 홈(모바일·PC), 상세(접수 중·마감), 찜(모바일·PC)
- 신청 표시(저장, 상세·찜·홈 반영, 되돌리기, 돌아왔을 때 한 번 묻기)
- 비슷한 접수 중 공고 추천 규칙

**범위 밖 (건드리지 않음)**
- 찾기(`/posters`) 화면 디자인. 단, 목록의 마감 표시는 4장의 함수를 같이 써서 홈과 어긋나지 않게 합니다.
- 마이, 기관 찾기, 포스터 제보, 관심 조건, 로그인 화면
- 푸시·카카오 알림 발송. 알림 대상 판정 함수(4.6)만 만들어 둡니다.
- 앞서 합의했지만 이 묶음에 화면이 없는 과제: 복합 검색어와 접수 상태 필터, 상세에서 목록으로 돌아올 때 위치 복원. 이 묶음이 끝난 뒤 따로 진행합니다.

### 1.3 현재 서비스에서 확인한 것 (2026-11-09, 화면 조작으로 확인)

- 경로: `/`(홈), `/posters`(찾기, 검색어 파라미터 `q`), `/posters/:id`(상세), `/my-posters`, `/interests`, `/institutions`, `/categories/*`, `/login`, `/posters/request`.
- Home v5의 홈 데이터: `/api/home` (파라미터 `pages, from, since, region, categories, follows`). 응답은 `{layout:{picks, deadline, followed, deadlineTotal, openTotal, freshSince, pages:[[{kind:'new'|'bundle'|'orgs', items}]], hasMore}, scopeLabel, shortcuts, from}`.
- 카드 항목: `id, title, org, imageWidth, imageHeight, imageStatus, applicationStartAt, deadline, deadlineType('fixed'|'until_exhausted'|'ongoing'), eventEndAt, tags, image, sourceUrl, posterStatus, organizerId, metaLine, benefitLine`와 `display{reception, receptionLabel, text, tone, daysLeft, dateTrusted, endDateLabel}`.
- **저장된 마감값에서 본 규칙성(12건)**: 원문에 시각이 있는 공고는 초가 `00`(예: `2026-11-11T14:59:00Z` = 서울 23:59:00), 날짜만 있는 공고는 `14:59:59Z`(서울 23:59:59)로 들어 있었습니다. 수집 코드에서 실제 규칙을 확인하세요. 이 차이에만 기대지 말고 확인 여부를 따로 저장합니다(4.1).
- 상세의 '신청 핵심 정보'(`#core-facts`) 항목: 접수 기간, 신청 대상, 비용, 모집 인원, 교육/운영 기간, 장소, 신청 방법, 연령, 주최/주관, 혜택, 문의. 값이 없으면 "원문에서 확인해 주세요".
- 상태 표기: 접수 중 / 접수 예정 / 접수 종료 / 마감일 확인 필요. 목록 표기: "11.19 마감 ·D-10", "오늘 마감", "소진 시 마감", "마감일은 원문에서 확인".
- 외부 링크 이름: "신청 페이지로 이동", "공식 공고 원문 보기", "공식 공고 확인하기".
- 이미지: `/_next/image`는 폭 360, 720만 받았습니다(다른 폭은 400 오류). 원본이 매우 큰 포스터가 있습니다(4500×5625, 1520×10686). 목록과 썸네일에는 줄인 이미지를 쓰세요.
- 글꼴: Noto Sans KR, Noto Serif KR이 이미 `next/font`로 들어 있습니다.
- 비회원도 찜과 관심 조건을 쓸 수 있었습니다. 브라우저 저장소 키 `posterlink.visitor_key`, `pl.visit.v1`을 봤습니다.
- 4021에는 "방문 이후 올라온 공고 N건"이 이미 있습니다(로그인하고 관심 조건을 저장한 사용자 한정이라고 전달받음).

## 3. 디자인 기준

값의 원본은 `reference/reference.css`의 `:root`와 컴포넌트 규칙입니다. 프로젝트의 스타일 방식(Tailwind 테마, CSS 변수 등)에 맞춰 옮기세요.

**색**

| 이름 | 값 | 쓰는 곳 |
|---|---|---|
| paper | `#F1EEE4` | 화면 바탕 |
| surface | `#FFFFFF` | 카드, 하단 바 |
| ink | `#1C2D4F` | 본문, 주요 버튼, 선택 상태 |
| ink-soft | `#3D4A66` | 보조 버튼 글자 |
| muted | `#5B5F6B` | 보조 글자 |
| faint | `#8A8D96` | 비활성 아이콘 |
| line / line-strong | `#E2DCCD` / `#DDD7C8` | 카드 테두리 / 칩·버튼 테두리 |
| stamp | `#BE3A2B` | **도장에만** 씁니다. 버튼·강조에 쓰지 않습니다 |
| ok / ok-bg | `#2F6B4F` / `#E3EEE6` | 무료, 신청 완료 |
| poster-bg | `#ECE7DA` | 포스터 뒤 바탕 |

**글꼴**: 제목·지역명·도장은 Noto Serif KR 700, 나머지는 Noto Sans KR 400/500/600/700.

**크기(모바일 390 기준)**: 화면 좌우 여백 16, 카드 모서리 12, 2열 간격 12, 하단 탭 68, 상세 하단 바 72, 상단 바 48. 글자 크기는 참조 CSS를 따릅니다(카드 제목 14/600, 마감 표시 11.5/600, 신청 자격 12.5, 기관 12, 상세 제목 19 명조).

**PC(1440 기준)**: 본문 폭 1200, 머리글 64, 4열 간격 20. 중간 폭은 시안이 없습니다. 프로젝트의 기존 분기점을 쓰고 열 수만 줄이세요(4 → 3 → 2).

**포스터 이미지**
- 카드의 포스터 칸은 5:7, `cover`, 위쪽 기준. 세로÷가로가 1.2 미만(정사각·가로형)이면 `contain`, 가운데.
- 상세 미리보기는 화면 높이의 40% 이하, 위쪽 기준으로 자르고 아래를 흐리게, "크게 보기"로 원본 전체를 엽니다.
- 포스터 위에는 도장과 찜 버튼만 올립니다. 날짜를 포스터 위에 올리지 않습니다(포스터의 제목·기관명을 가립니다).

**제목 표시**: 꺾쇠 안쪽 공백은 지우고(`< 제목 >` → `<제목>`), 꺾쇠 안쪽(여는 꺾쇠 뒤, 닫는 꺾쇠 앞)과 가운뎃점 앞뒤에서는 줄이 끊기지 않게 해 꺾쇠·가운뎃점이 줄 끝이나 줄 머리에 홀로 남지 않게 합니다. 여는 꺾쇠 **앞**의 띄어쓰기는 일반 띄어쓰기로 둡니다. "기관명 <첫 단어"가 한 줄에 들어가지 않을 때만 그 자리에서 줄이 바뀌고, 꺾쇠는 다음 단어와 함께 내려갑니다(예: `성동청소년문화의집` / `<2026 MZ마음상담…`). 한글은 단어 단위로 줄을 바꾸고, 한 단어가 한 줄보다 길 때만 그 단어 안에서 줄을 바꿉니다. 카드 밖으로 글자가 넘치지 않게 합니다. 제목은 정해진 줄 수를 넘으면 말줄임하고, 신청 조건 꼬리표는 말줄임하지 않습니다. (2026-11-11, PR #30)

**아이콘**: 참조의 아이콘은 Feather 계열 선 아이콘(24 기준, 굵기 2)입니다. 프로젝트에 아이콘 묶음이 있으면 그것을 쓰세요.

## 4. 마감 표시 규칙

같은 공고의 마감 표시는 **어느 화면에서나 한 함수에서** 나와야 합니다(홈, 찾기, 상세, 찜, 비슷한 공고).

### 4.1 필요한 데이터

| 뜻 | 제안 이름 | 설명 |
|---|---|---|
| 접수 방식 | `deadline_kind` | `fixed` 정해진 마감 / `per_session` 회차별 / `until_full` 정원·예산 소진 시 / `rolling` 상시·반복 예약 / `unknown`. 기존 `deadlineType`을 넓힙니다 |
| 접수 마감일 | `apply_deadline_date` | 서울 날짜 |
| 접수 마감 시각 | `apply_deadline_time` | 원문에 적힌 경우만. 없으면 비움 |
| 마감일 확인 상태 | `deadline_status` | `verified` / `unverified` / `conflict`(출처끼리 다름) |
| 시각 확인 여부 | `deadline_time_verified` | **값이 저장돼 있다는 것만으로 참으로 두지 않습니다** |
| 확인 근거 | `deadline_source` | `poster` / `notice` / `apply_page` |
| 접수 중 확인 | `reception_verified` | 지금 접수 중인지 확인했는가 |
| 회차별 조건 | `session_rule_text`, `session_rule_verified`, `last_session_deadline_date` | 예: "각 클래스 전날까지 접수" |
| 표시 문구 | `deadline_label` | `until_full`, `rolling`용. 예: "정원 마감 때까지", "매월 선착순 예약" |
| 마감 덧말 | `deadline_note` | 상세의 마감 아래 한 줄. 예: "조기 마감될 수 있어요" |
| 행사·교육 기간 | `event_start_at`, `event_end_at` | **접수 마감과 따로 저장** |
| 선정 안내 일시 | `selection_notice_at` | 확인된 경우만 |

기존 `display.dateTrusted`가 같은 뜻이면 새로 만들지 말고 넓혀 쓰세요.

### 4.2 판정 순서 (위에서부터 먼저 맞는 것)

1. 이용자가 신청 표시함 → **신청함** (이용자별 덧씌움, 5장)
2. 접수가 끝남 → **마감**
3. `fixed` + 마감일 확인 + 시각 확인 → **날짜·시각 확인**
4. `fixed` + 마감일 확인 + 시각 없음 → **날짜만 확인**
5. `per_session` → 조건 확인됨이면 **회차별**, 아니면 **회차별(확인 전)**
6. `until_full`, `rolling` → **문구 표시**
7. 그 밖(`unknown`, `unverified`, `conflict`) → 접수 중이 확인됐으면 **마감일 미확인**, 아니면 **접수 여부 미확인**

### 4.3 상태별 표시

| 상태 | 카드의 마감 표시 | 상세 '신청 마감' | 도장 | D-day | 상태 태그 | 마감 안내 |
|---|---|---|---|---|---|---|
| 날짜·시각 확인 | `11.12(목) 오후 6시까지` | 같은 문구, 오른쪽에 `D-3` | D-3~오늘 | 표시 | 접수 중 | 확인된 시각까지 |
| 날짜만 확인 | `11.15(일)까지`. 당일은 `오늘이 마감일 · 시각 확인` | `11.15(일)까지` + 아래에 "마감 시각은 공고문에서 확인" | D-3~D-1, 당일 `오늘` | 표시 | 접수 중 | **하루 전까지만** |
| 회차별 | `각 클래스 전날까지 접수` | `각 클래스 전날까지`, 오른쪽에 "마지막 접수 12.13(일)", 아래에 "11.11(수) 클래스는 11.10(화)까지" | 없음 | 없음 | 접수 중 | 없음 |
| 회차별(확인 전) | `회차별 접수 조건 확인` (흐리게) | "신청 페이지에서 확인" | 없음 | 없음 | 접수 중 | 없음 |
| 문구 표시 | `정원 마감 때까지`, `매월 선착순 예약` | 같은 문구 | 없음 | 없음 | 접수 중 | 없음 |
| 마감일 미확인 | `마감일은 공고문에서 확인` (흐리게) | "공고문에서 확인" + 설명 한 줄 | 없음 | 없음 | 접수 중 | 없음 |
| 접수 여부 미확인 | `접수 여부 확인` (흐리게) | "공고문에서 확인" | 없음 | 없음 | **접수 여부 확인** | 없음 |
| 마감 | (홈에 안 나옴) 목록에서는 `8.17 마감` | 배너 "이 공고는 8월 17일에 접수가 끝났어요" | 없음 | 없음 | 접수 종료 | 없음 |
| 신청함 | `✓ 신청했어요` (초록) | 마감 값은 그대로, D-day 숨김 | 숨김 | 숨김 | 그대로 | 제외 |

- 목록 행(찜, 비슷한 공고)은 폭이 넓으므로 긴 문구를 씁니다: `회차별 접수 조건은 신청 페이지에서 확인`. 도장이 없는 행은 날짜 뒤에 D-day를 붙입니다: `11.26(목) 오후 1시까지 · D-17`.
- **회차별 공고의 마지막 회차 날짜를 공고 전체의 마감처럼 쓰지 않습니다.**
- 운영 기간의 끝(예: 연말)을 접수 마감으로 쓰지 않습니다. 매달 예약을 받는 상담 같은 공고는 `rolling`입니다.
- 마감일 미확인의 설명 한 줄: 출처끼리 다를 때 "마감일이 서로 다르게 올라와 있어 확인하고 있어요. 확인 전에는 D-day와 마감 알림을 표시하지 않아요."

### 4.4 날짜·시각 쓰는 법

- 날짜: `11.12(목)`. 올해가 아니면 연도를 붙입니다(`2027.1.5(화)`).
- 시각: 정각이면 `오전 9시`, `오후 6시`. 분이 있으면 `밤 11시 59분`. 1~11시 오전, 12시 낮, 13~20시 오후, 21~23시 밤.
- **2열 카드에서 분이 있는 시각은 `23:59까지`로 줄입니다**(한 줄에 들어가지 않습니다). 상세와 목록 행은 `밤 11시 59분까지`. 형식 함수에 '짧게' 옵션 하나로 두세요. → 12장 A-2
- 끝은 항상 "까지".

### 4.5 D-day와 도장

- D-n = 접수 마감일 − 오늘(둘 다 서울 날짜).
- 도장은 n이 3, 2, 1일 때 `D-3`, `D-2`, `D-1`, 0일 때 `오늘`. 그 밖에는 없음.
- 날짜·시각 확인: 당일 그 시각이 지나면 마감. 날짜만 확인: 그날이 끝날 때까지 접수 중, 다음 날 0시에 마감.
- 날짜만 확인된 공고의 당일에는 남은 시간이나 "자정까지"를 쓰지 않습니다.

### 4.6 마감 안내 대상

`찜함` 그리고 `신청 표시 안 함` 그리고 상태가 `날짜·시각 확인` 또는 `날짜만 확인` 그리고 `0 ≤ n ≤ 3`.

- 알림 발송(나중): 날짜·시각 확인은 그 시각까지, 날짜만 확인은 하루 전까지만.
- 홈의 찜 마감 줄 문구는 9장.

### 4.7 기존 데이터

- 시각: 확인 표시가 없는 시각은 보여주지 않습니다. 기존 값을 한꺼번에 '확인됨'으로 바꾸지 마세요.
- 날짜: 기존 날짜를 어떻게 다룰지는 정해지지 않았습니다. → 12장 A-1. 권장안으로 구현하되 정책을 한 곳에서 바꿀 수 있게 하세요.
- 자동으로 내릴 것(권장): **접수 마감일이 행사·교육 시작일이나 종료일과 같으면 '확인 전'으로** 둡니다. 시안을 만들며 원문과 대조한 공고 가운데 두 건이 이 경우였습니다(부록 A의 강사단 교육, 집 보는 수업).

## 5. 신청 표시

- **이용자가 직접 눌러야만** 신청함이 됩니다. 신청 페이지를 연 것만으로는 바뀌지 않습니다.
- 저장은 찜과 같은 방식으로(비회원은 브라우저, 로그인 사용자는 서버, 로그인 시 합침).
- 누르는 곳: 상세의 '신청했어요' 버튼(임박하지 않은 공고에도 있음), 찜 목록 행의 '신청했어요', 돌아왔을 때 안내.
- 신청함이 되면
  - 홈·목록 카드: 마감 표시가 `✓ 신청했어요`로 바뀌고 도장이 사라집니다.
  - 홈의 찜 마감 줄 집계에서 빠집니다.
  - 찜: '신청한 공고' 묶음으로 옮겨지고, 아래에 "'신청한 공고'로 옮겼어요 · 되돌리기"가 잠깐 뜹니다.
  - 상세: 초록 띠 "✓ 신청한 공고예요 · 되돌리기 / 마감 알림을 껐어요"가 보입니다. 선정 안내 일시가 확인된 공고만 " · 선정 안내 11.12(목) 오후 3시 예정"을 붙입니다. '신청했어요' 버튼은 선택 상태(초록), 주요 버튼은 외곽선으로 바뀝니다.
- **되돌리기**는 상세, 찜 어디서든 즉시 됩니다. 찜 여부는 그대로입니다.
- 찜하지 않은 공고에 신청 표시를 해도 찜의 '신청한 공고'에 보입니다.

**돌아왔을 때 한 번 묻기**
- 조건: 이 공고의 '신청 페이지로 이동'을 누르고 화면으로 돌아왔고, 아직 신청함이 아니고, 이 공고에서 이 안내를 보여준 적이 없음.
- 내용: "신청을 마치셨나요? / 신청했다고 표시하면 이 공고의 마감 알림이 꺼져요. / [신청했어요] [아직이에요]"
- 안내가 떠 있는 동안 하단 바의 '신청했어요' 버튼은 숨깁니다(같은 버튼이 둘이 되지 않게).
- '아직이에요'를 누르면 닫고 다시 묻지 않습니다. 하단 바의 버튼은 다시 나옵니다.

## 6. 공고 카드

위에서부터: 포스터(도장, 찜 버튼) → 마감 표시 → 짧은 제목(2줄까지) → 신청 자격(2줄까지, PC는 1줄) → 기관(1줄).

| 항목 | 내용 | 값이 없을 때 |
|---|---|---|
| 짧은 제목 | 기관명·연도·"안내" 같은 앞뒤를 뗀 제목. 무엇을 하고 누구를 모집하는지는 남기고, 기수·차수는 남깁니다(`공유주방 25기 및 제조주방 13기 모집`) | 공식 제목을 그대로 |
| 신청 자격 | **확인된** 대상 조건. 거주 조건이 있으면 넣습니다(`서울 거주 무주택 신혼부부`). 기관이 있는 구를 거주 조건처럼 쓰지 않습니다 | 줄을 비움. 지어내지 않습니다 |
| 기관 | 대표 기관 하나(`강북구청`) | 기관 문자열의 첫 기관 |

- 행사 장소는 카드에 쓰지 않습니다(상세와 찜의 '진행'에만).
- 짧은 제목과 신청 자격은 사람이 확인한 값만 씁니다. 누가 언제 채울지는 12장 A-5.
- 상태 예시는 `reference/index.html`의 1번 묶음과 `screens/cards-deadline-*.png`.

## 8. 비슷한 접수 중 공고

**순서**
1. 같은 주제·같은 대상, 같은 구
2. 같은 주제·같은 대상, 서울의 다른 구 — 넓혀 찾았음을 표시
3. 같은 주제, 누구나 참여할 수 있는 공고
4. 같은 주제, 대상이 다른 공고 — **따로 묶어** "같은 주제 · 대상이 다른 공고"(대상이 하나로 모이면 "같은 주제 · 청년 대상")로 보여주고, 조건을 제목보다 먼저 씁니다.

- 1~2건만 보여줍니다. 자리를 채우려고 관련이 약한 공고를 넣지 않습니다. 모자라면 "접수 중인 ○○ 공고 모두 보기"로 잇습니다.
- 같은 주제·대상이 없으면 그 사실을 한 줄로 알립니다("1인가구 대상 공고는 지금 없어요").
- 다른 구까지 넓혔으면 "서울 다른 구까지 넓혀 찾음"을 표시합니다.
- 주제가 붙지 않은 공고는 추천을 지어내지 말고 "모두 보기" 링크만 둡니다. → 12장 B
- 접수 여부가 확인되지 않은 공고는 추천하지 않습니다.

**지역과 신청 자격** — 이용자가 고른 지역은 '둘러보는 지역'이지 거주지가 아닙니다.

## 11. 검수

**먼저 볼 세 가지**
1. 원문에 23:59가 적힌 공고(가죽공방)와 저장값만 23:59인 공고(포인트 노동법)가 다르게 보이는가.
2. 회차별 공고(송파 잡톡)의 마지막 날짜가 공고 전체의 마감으로 보이지 않는가. 도장·D-day·마감 안내가 없는가.
3. 신청 표시와 되돌리기가 홈·상세·찜에 함께 반영되는가.

**화면**
- 390×844: 첫 방문 홈에서 첫 포스터가 약 170px에서 시작. 상세에서 요약과 버튼이 스크롤 없이 보임. 마감 상세에서 대안 공고까지 한 화면.
- 1440×900: 홈 첫 줄 카드의 제목·정보가 보임. 상세의 버튼이 첫 화면에 있음.
- 긴 포스터(세로가 가로의 7배)와 정사각 포스터에서 카드와 상세가 깨지지 않음.
- 주홍색이 도장 밖에 쓰이지 않음.

**잘못된 안내가 나가지 않는가**
- 마감일이 출처끼리 다른 공고에 도장·D-day·마감 안내가 없음.

- 신청함으로 표시한 공고가 홈의 찜 마감 줄에 세어지지 않음.

## 12. 정해지지 않은 것

### A. 대표가 정할 것 (답이 오기 전에는 권장안으로)

1. **기존 마감 날짜를 어떻게 다룰지.** 권장: 기존에 '믿을 수 있음'으로 표시된 날짜는 '날짜만 확인'으로 계속 보여주고, 시각은 확인 표시가 있을 때만 보여주며, 4.7의 자동 규칙으로 의심스러운 날짜를 내립니다. 대안: 근거를 확인한 공고만 날짜를 보여줍니다(더 안전하지만 처음에는 대부분의 카드에 날짜가 없습니다).
2. **2열 카드의 분 단위 시각.** 권장: 카드는 `23:59까지`, 상세는 `밤 11시 59분까지`.
3. **'비슷한 공고 받기'가 하는 일.** 권장: 기존 관심 조건 저장에 주제·지역을 채워 잇습니다. 그것이 어렵다면 이번에는 버튼을 숨깁니다.
4. **PC 머리글에서 빠진 '기관 찾기', '포스터 제보'와 '마이'의 내용.** 권장: 경로는 그대로 두고 마이 화면과 바닥글에서 잇습니다. 마이는 기존 계정 화면(로그인 전이면 로그인)으로.
5. **짧은 제목, 신청 자격, 주제를 누가 언제 채우는지.** 권장: 접수 중 공고부터 초안을 일괄로 만들고 사람이 확인한 것만 화면에 씁니다. 그 전까지는 6장의 '값이 없을 때'대로 보입니다.
6. **'집 보는 수업'의 회차별 접수 조건.** 기관에 확인이 필요합니다(부록 A).

### B. 시안에 없어 권장안으로 채운 것

- 상세 첫 화면 아래의 구성(기존 구성 유지).
- 찜 마감 줄의 여러 건 문구.
- 주제가 없는 공고의 추천(링크만).
- 찜하지 않은 공고의 신청 표시가 찜의 '신청한 공고'에 보이는 것.
- '공식 공고 확인하기'만 있는 공고에서는 돌아왔을 때 안내를 띄우지 않는 것.
- 회차별(확인 전)과 마감일 미확인(충돌 아님)의 상세 문구.
- 접수 예정 공고의 표시(기존 그대로).
- 시각 표현의 오전·낮·오후·밤 구분, 올해가 아닌 날짜의 연도 표기.
