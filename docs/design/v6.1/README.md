# PosterLink v6.1 개발 전달 묶음

홈·상세·찜의 새 디자인(v6.1)을 Claude Code나 Codex가 구현할 수 있게 정리한 묶음입니다.

## 들어 있는 것

| 파일 | 내용 |
|---|---|
| `SPEC.md` | 구현 명세. 규칙, 화면, 문구, 작업 순서, 정해지지 않은 것 |
| `reference/build_reference.mjs` | 화면과 컴포넌트의 구조(템플릿 함수). 컴포넌트로 옮길 때 이 파일을 읽습니다 |
| `reference/reference.css` | 색·크기 값과 컴포넌트 스타일 |
| `reference/index.html` | 위 둘로 만든 참조 화면. 브라우저로 열어 봅니다 |
| `screens/*.png` | 실제 포스터가 들어간 시안. 모바일 13장, PC 3장, 카드 상태 2장 |
| `fixtures/deadline-cases.json` | 마감 표시 검수 사례 20개 |
| `fixtures/sample-postings.json` | 시안에 쓴 실제 공고 14건의 id와 원문 근거 |

## 쓰는 법

1. 이 폴더를 저장소의 `docs/design/v6.1/`에 넣습니다.
2. Home v5(로컬 4021로 띄우던 쪽) 브랜치에서 Claude Code나 Codex를 열고 아래를 붙여 넣습니다.

```
docs/design/v6.1/SPEC.md를 끝까지 읽고 10장의 0단계만 진행해 주세요. 코드는 아직 고치지 마세요.
지금 브랜치가 Home v5(로컬 4021로 띄우던 쪽)가 맞는지 먼저 확인하고, 아니면 알려 주세요.
끝나면 다음을 정리해 주세요.
1) 명세의 각 항목이 어느 파일과 테이블에 해당하는지
2) 빠져 있는 데이터 항목과 추가 방법
3) 명세와 지금 코드가 부딪히는 곳
4) 저에게 물어볼 것 (SPEC 12장 A 포함)
```

3. 계획을 확인한 뒤 한 단계씩 시킵니다.

```
SPEC.md 10장의 1단계를 진행해 주세요. fixtures/deadline-cases.json으로 테스트를 먼저 쓰고,
완료 기준을 확인한 결과를 보여 주세요. 다음 단계는 제가 말할 때 시작해 주세요.
```

화면 단계(3~7)에서는 이렇게 덧붙이면 좋습니다.

```
구현한 화면을 390×844와 1440×900으로 캡처해서 docs/design/v6.1/screens의 같은 이름 이미지와 비교하고,
다른 점을 알려 주세요.
```

4. 이후 작업에서도 명세를 따르게 하려면 저장소의 `AGENTS.md`(Codex)나 `CLAUDE.md`(Claude Code)에 한 줄을 넣습니다.

```
홈·상세·찜 화면과 마감 표시는 docs/design/v6.1/SPEC.md를 따른다. 명세와 다르게 구현해야 하면 먼저 묻는다.
```

## 먼저 정하실 것

`SPEC.md` 12장 A의 여섯 가지입니다. 답이 없어도 권장안으로 진행되지만, 첫째는 화면 전체의 모습을 바꿉니다.

1. **기존 마감 날짜를 어떻게 다룰지** — 지금처럼 보여주되 의심스러운 것만 내릴지, 근거를 확인한 것만 보여줄지
2. 2열 카드의 분 단위 시각 표기
3. '비슷한 공고 받기'가 하는 일
4. PC 머리글에서 빠진 '기관 찾기', '포스터 제보'의 자리
5. 짧은 제목·신청 자격·주제를 누가 언제 채우는지
6. '집 보는 수업'의 회차별 접수 조건(기관 확인)

## 알아둘 것

- 명세는 코드를 보지 않고, 실행 중인 화면을 조작해 확인한 내용으로 썼습니다. 그래서 0단계에서 코드와 맞춰 보게 했습니다.
- 시안의 날짜와 D-day는 2026-11-09(월) 기준입니다.
- 어떤 공고를 찜·신청했는지와 "지난 방문 이후 14건"은 예시입니다.
- 참조 화면의 포스터 자리는 빈 칸입니다. 실제 모습은 `screens/`를 보세요.
- `reference/index.html`을 다시 만들려면 `reference` 폴더에서 `node build_reference.mjs index.html`.
