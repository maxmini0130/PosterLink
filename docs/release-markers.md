# 변경 적용일 기록

재방문·가입 전환 지표의 전후 비교 기준. 운영에 실제 반영된 시점만 기록한다. 준비·승인 대기 상태는 "미반영"으로 둔다. 시각은 KST.

| 반영 시각 (KST) | 단계       | 변경 내용                                                                                                  | 운영 SHA / 배포 | DB 마이그레이션                                                                                                                    | 비고                                                                                                |
| --------------- | ---------- | ---------------------------------------------------------------------------------------------------------- | --------------- | ---------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| 미반영          | 0단계 측정 | `product_events` 확장, 익명 식별자·계정 연결, 공고 조회 출처, 공유·찜·구독·관심 조건·가입 시작/완료 이벤트 | —               | `20261031010000_extend_product_events_for_retention.sql` — **2026-11-01 00:57 KST 이전 운영 적용 확인** (SQL Editor, BEGIN~COMMIT) | 웹 미배포라 아직 새 이벤트는 기록되지 않음. 반영 시각은 PR #16 운영 배포 시각(늦은 쪽)으로 확정한다 |

## 기록 방법

- 운영 배포 확인 직후 한 행을 추가한다. 웹 배포와 DB 마이그레이션 시각이 다르면 둘 중 **늦은 시각**을 반영 시각으로 쓰고 비고에 둘 다 남긴다.
- 롤백하면 별도 행으로 기록한다. 기존 행을 지우지 않는다.
- 비교 쿼리는 [retention_metrics_20261031.md](retention_metrics_20261031.md)를 사용한다.
