# PosterLink 모바일 UI 개편 지시서 (2026-10-31)

> 대상: Claude Code
> 함께 볼 문서: `docs/RETENTION_PLAN_2026-10-31.md` (재방문·가입 개선 지시서. 이하 "재방문 지시서")
> 시안 참고 파일: `docs/design/posterlink-mobile-v3/` (화면별 HTML 시안 11개 + `canvas.json`)
> 범위: 공고 상세 → 내 공고 → 홈·찾기 → 관심 조건(온보딩) 화면의 UI 개편 (웹 기준, 앱 WebView에도 그대로 반영)
> 범위 밖: 마이 탭, 포스터 제보 화면, 앱 네이티브 기능(푸시·카메라·공유 시트), 알림 발송

---

## 0. 원칙

1. **재방문 지시서와 한 몸입니다.** 이 문서는 화면을, 재방문 지시서는 데이터·동작을 정의합니다. 각 화면이 필요로 하는 데이터(지역 구분, 비회원 찜, 지난 방문 기준, 신청 표시 등)는 재방문 지시서의 해당 단계가 준비된 뒤에 연결합니다. 데이터가 아직 없으면 그 섹션은 **숨김** 처리하고, 가짜 데이터로 채우지 않습니다.
2. **기존 코드 재사용.** 현재 컴포넌트·라우트·스타일 체계를 먼저 조사해 보고하고, 새로 만들기보다 교체·확장합니다. 기존 브랜드 시스템(잉크 네이비·종이 베이지·주홍, D-day 도장)을 유지합니다.
3. **운영 DB 쓰기·마이그레이션 적용·배포·push 금지.** 승인 후 진행합니다. Preview가 운영 DB에 연결되어 있으므로 Preview에서도 쓰기 동작은 테스트하지 않습니다.
4. **모바일 우선, PC는 별도 배치.** 모바일 시안은 390px, PC 시안은 1280px 기준입니다(`PcDetail`, `PcHome`, `PcSearch`). PC 배치 규칙은 3-1장을 따르고, 폭이 줄면 모바일 정보 순서로 자연스럽게 돌아가야 합니다.
5. **화면 단위로 나눠 반영합니다.** 순서: ① 공고 상세 → ② 내 공고 → ③ 홈·찾기 → ④ 관심 조건 선택. 각 단계마다 별도 커밋·보고.

### 시안 파일 보는 법

`docs/design/posterlink-mobile-v3/*.dc.html`은 디자인 도구용 HTML이라 브라우저로 열면 일부 값(`{{accent}}` 등)이 그대로 보일 수 있습니다. **레이아웃·문구·순서의 참고용**이며, 코드를 그대로 옮기지 말고 프로젝트의 컴포넌트 체계로 구현합니다. `{{accent}}` = `#BE3A2B`.

## 1. 디자인 기준

### 1-1. 색 (기존 토큰이 있으면 그 이름으로 매핑)

| 용도 | 값 |
|---|---|
| 본문·제목 (ink) | `#1C2D4F` |
| 배경 (paper) | `#F1EEE4` |
| 카드 면 | `#FFFFFF` |
| 카드 테두리 | `#D9D3C3` |
| 카드 안 구분선 | `#ECE7DA` |
| 보조 글자 (설명·라벨) | `#4A4E59` |
| 메타 글자 (기관명·출처) | `#5B5F6B` |
| 강조 (마감·주요 버튼·D-day 도장) | `#BE3A2B` |
| 포스터 자리·썸네일 배경 | `#E2DCCB` |
| 카카오 버튼 | `#FEE500` / 글자 `#191919` |
| 네이버 버튼 | 흰 바탕 + 테두리 `#D9D3C3` + 초록 N 로고 `#03C75A`, 글자 ink (초록 바탕에 흰 글자는 대비 4.5:1 미달이므로 쓰지 않음. 네이버 로그인 버튼 가이드의 흰색 변형 사용) |

- 글자 대비 4.5:1 이상. 위 조합은 모두 충족합니다. 새 조합을 만들면 대비를 확인합니다.
- 색만으로 상태를 구분하지 않습니다. 마감·상시·종료는 **글자**로도 표시합니다.

### 1-2. 글꼴·크기

- 제목(화면 제목, 공고 제목): **Noto Serif KR** 700 (프로젝트에 이미 다른 명조가 있으면 그것 유지)
- 본문: **Noto Sans KR** 400/500/700
- 크기: 화면 제목 22–24 / 섹션 제목 15–17 / 카드 제목 14–15 / 본문 14 / 메타 12–13 / 최소 11.5px
- 공고 제목 줄 간격 1.38–1.4

### 1-3. 형태

- 모서리: 버튼 8–10px, 카드 10–12px, 바텀시트 20px(위쪽)
- 터치 영역 최소 44×44px
- 화면 좌우 여백 20px, 카드 사이 8–10px, 섹션 사이 20–28px
- 그림자는 토스트·바텀시트·제보 버튼에만

## 2. 공통 컴포넌트

| 컴포넌트 | 내용 |
|---|---|
| **마감 표시 (DeadlineLabel)** | 공고 접수 상태(재방문 지시서 3-1의 공용 함수)로만 결정. `D-n`(강조색), `오늘 마감`(강조색 배경 칩), `상시 모집`, `소진 시 마감`(ink), `접수 예정`, `접수 종료`(회색). **마감일 확인 필요** 공고는 D-day를 표시하지 않고 "마감일은 원문에서 확인"으로 표시 |
| **D-day 도장 (DdayStamp)** | 상세 상단 제목 옆. 원형 이중 테두리, -8° 회전, `D-5` + `11.05 마감`. 날짜 신뢰 공고에만 표시 |
| **공고 카드 (PosterCard)** | 썸네일(56×72) + 분야·기관 한 줄 + 제목(2줄까지) + 마감 표시. 카드 전체가 링크 |
| **작은 가로 카드** | 홈 "7일 안에 마감"용, 폭 168px 가로 스크롤 |
| **지역 라벨 (RegionLabel)** | `주변 지역`, `서울 전체`, `전국` 작은 칩. 확장 묶음의 카드에 표시 |
| **섹션 머리 (SectionHeader)** | 제목 + 아래 한 줄 조건 표시(예: "마포구 대상 · 문화/행사 · 접수 중") |
| **하단 행동 바** | 상세 화면 하단 고정. 왼쪽 `찜하기`(아이콘+글자), 오른쪽 주 버튼 |
| **하단 탭 (TabBar)** | 홈 / 찾기 / 내 공고 / 마이. 현재 탭은 굵게 + `aria-current="page"` |
| **포스터 제보 버튼** | 홈 화면 우하단 떠 있는 버튼. 이번 범위에서는 링크 자리만(제보 화면은 범위 밖) |
| **토스트** | 화면 하단(탭·행동 바 위), 한 줄 + 행동 링크 1개, 자동으로 사라짐 |
| **바텀시트** | 손잡이 + 제목 + 내용 + 주 버튼 + "나중에 할게요" |
| **신청 표시 (ApplyMark)** | 표시 전: `신청했어요` 버튼 / 표시 후: `신청 표시됨` 칩 + `표시 취소`. 표시 직후 마감 알림이 켜져 있으면 "신청했으니 이 공고의 마감 알림은 끌까요? [알림 끄기] [계속 받기]" |
| **안내 카드 (GuideCard)** | 빈 섹션 대신 쓰는 한 장짜리 안내(예: "자주 보는 기관을 구독해 보세요") |

## 3. 화면별 명세

시안 번호는 `canvas.json`의 보드 제목 번호와 같습니다.

### ① 공고 상세 · 접수 중 (`Main.dc.html`)

정보 순서(위→아래):
1. 상단 바: 뒤로, "공고 상세", 공유
2. 분야·대상 지역·접수 상태 칩 → 공고 제목 → 기관명 / 오른쪽에 D-day 도장
3. **신청 핵심 정보** 카드: 접수 기간 · 대상 지역 · 모집 인원 · 신청 대상 · 신청 방법
   - 값이 없는 항목은 "원문에서 확인해 주세요 · 원문 보기" (원문 링크를 바로 옆에)
   - 카드 아래: "신청을 마쳤다면 직접 표시해 두세요" + `신청했어요` 버튼
4. 포스터 (높이 240px, `크게 보기`) + `공고 원문 전체 보기`(접힘, 펼치면 원문)
5. 기관 카드 + `구독`
6. "○○구에서 지금 신청할 수 있어요" 관련 공고 카드 3개 + 더 보기 (재방문 지시서 1-3 기준)
7. 주변 지역 공고 (조건 충족 시에만, `주변 지역` 라벨)
8. 출처 안내 한 줄
9. 하단 행동 바: `찜하기` / 주 버튼. **신청 링크(apply_url)가 확인된 공고만 `신청 페이지로 이동`**, 없으면 `공식 공고 확인하기`(official_url)

- 지금처럼 원문 텍스트를 상세에 그대로 펼쳐 놓지 않습니다.
- "마감 전 알림 받기"는 상세 기본 화면에 두지 않습니다(찜 후 내 공고에서 설정).

### ② 찜 직후 (`Saved.dc.html`)

- 비회원이 찜하면 **토스트**: "이 기기에 저장됐어요 · 계정에 보관하기"
- 찜 버튼은 `찜함` 상태(강조색)로 바뀜
- 큰 가입 창을 바로 띄우지 않습니다.

### ③ 계정에 보관하기 (`SaveSheet.dc.html`)

- 토스트의 "계정에 보관하기"를 누르면 바텀시트
- 이점 2가지만: "다른 기기에서도 찜한 공고를 이어서 볼 수 있어요" / "관심 지역과 기관의 새 공고를 모아 볼 수 있어요"
- `카카오로 계속하기` / `네이버로 계속하기` (iOS 앱에서는 `Apple로 계속하기` 추가) / `나중에 할게요` / "이 기기에 찜한 공고는 계정으로 그대로 옮겨져요"
- 가입 완료 후 원래 화면으로 복귀 + 하려던 행동 완료(재방문 지시서 2-3)

### ④ 공고 상세 · 접수 종료 (`Closed.dc.html`)

순서:
1. 원래 공고의 칩(`접수 종료` 회색) → 제목 → 기관 / 작은 포스터 썸네일
2. 남색 띠: "이 공고는 ○월 ○일에 접수가 끝났어요" + "같은 분야 · ○○에서 지금 신청할 수 있는 공고" 카드(최대 3, 관련성 낮으면 줄임)
3. **내 기록** 카드(신청 표시한 회원만): `신청 표시됨` + "내가 직접 표시한 기록이에요. 공고가 끝나도 그대로 남아요." + 결과 안내 + `표시 취소`
   - 결과 안내 문구: "공고에 적힌 결과 안내일 / ○월 ○일(요일) · 방식 / 실제 발표 여부는 기관에 확인해 주세요"
   - **지난 날짜에 "예정"이라고 쓰지 않습니다.**
4. 공고 정보(접수 기간(종료) · 신청 대상 · 모집 인원 · 교육/운영 기간 · 장소) — 결과 안내일과 운영 기간을 섞지 않음
5. 원문 보기
6. 하단: "비슷한 공고 받기: **교육강좌 · 서울** 조건으로 저장돼요 · 조건 바꾸기" + `공식 공고 확인하기` / `비슷한 공고 받기`
   - 신청 버튼은 표시하지 않습니다.

### ⑤ 관심 지역·분야 고르기 (`Onboarding.dc.html`)

- **앱을 직접 처음 열 때만** 표시. 검색·공유·푸시로 들어온 경우 공고부터 보여줌. 찜하거나 홈으로 갈 때 설정을 제안
- 지역: 자치구 단위 칩(선택됨/추가), "관심 지역은 언제든 바꿀 수 있어요"
- 분야: 2열 버튼(기존 분류: 지원금/복지, 교육/취업, 문화/행사, 주거/금융, 소상공인, 육아/가족, 건강/의료, 전체 분야), 복수 선택, `aria-pressed`
- 상단 `건너뛰기`, 하단 `○○구 공고 보기`
- 가입 없이 이 기기에 저장, 가입 후 그대로 이어받음

### ⑥⑦⑧ 홈 (`HomeFirst` / `Home` / `HomeQuiet`)

공통: 상단에 로고 + 관심 조건 버튼("마포구 · 관심 분야 3"), 하단 탭, 포스터 제보 버튼.

| 상태 | 첫 섹션 | 그 아래 |
|---|---|---|
| ⑥ 첫 방문 | "○○구에서 지금 신청할 수 있는 관심 공고" + 모두 보기 | 안내 카드 "마음에 드는 공고를 찜해 두면, 다음에 오셨을 때 새 공고와 함께 모아 보여드려요" |
| ⑦ 재방문·새 공고 있음 | 작은 글자 "○월 ○일(요일) 방문 이후" + "새로 올라온 관심 공고 N건" (3건 + "새 공고 n건 더 보기") | 7일 안에 마감(가로 카드, 찜한 공고는 `찜` 표시) → 구독 기관 소식 → 접수를 시작한 찜 공고(있을 때만) → 서울 전체 대상 |
| ⑧ 재방문·새 공고 없음 | 작은 글자 "○월 ○일 방문 이후 새 관심 공고는 아직 없어요" + "7일 안에 마감되는 관심 공고" | 찜·구독이 없으면 안내 카드 하나("자주 보는 기관을 구독해 보세요" + 기관 둘러보기) |

- "지난 방문" 기준은 재방문 지시서 3-2 규칙 그대로. 새 공고를 열었다 돌아와도 나머지 새 공고 표시는 유지
- 비어 있는 섹션은 숨김. 빈 섹션을 여러 개 보여주지 않음

### ⑨ 내 공고 · 비회원 (`MyPostsGuest.dc.html`)

- 상단 카드: "이 기기에 찜한 공고 N개" + "계정에 보관하면 다른 기기에서도 이어서 보고, 마감 알림과 신청 표시도 쓸 수 있어요" + `카카오로 계속하기` / `네이버로 계속하기` (iOS 앱은 Apple 추가)
- 목록: 찜만 표시, 각 카드에 "이 기기에 저장됨" + `찜 취소`
- 알림·신청 표시·구독 탭은 비회원에게 보여주지 않음(계정 기능으로 안내)

### ⑩ 내 공고 · 회원 (`MyPosts.dc.html`)

- 가입 직후에는 상단에 닫을 수 있는 안내: "이 기기에 찜한 공고 N개를 계정으로 옮겼어요"
- 탭: `찜 N` / `신청 표시 N` / `구독 기관 N`
- 찜 탭: **공고 접수 상태별 묶음**(접수 예정 → 접수 중 → 접수 종료, 빈 묶음 숨김)
- 카드 하단 행동:
  - 날짜 신뢰 공고: `마감 알림 받기`(켜지면 상태 표시) + 신청 표시
  - 상시·소진 시 마감: "마감일이 없는 공고라 날짜 알림은 없어요" + 신청 표시
  - 종료 공고: 결과 안내일 + 신청 표시 상태
- **"알림 켜짐"은 수신 동의와 기기 권한이 확인된 경우에만** 표시. 확인 전에는 켜짐으로 보이지 않게

### ⑪ 찾기 (`Search.dc.html`)

1. 검색 입력(라벨 포함)
2. 저장한 조건 칩(선택 / 다른 조건 / `지금 조건 저장`)
3. 필터 칩: 지역, 분야, `접수 중만`, 정렬
4. 결과는 **세 묶음으로 분리**, 섞지 않음:
   - **선택한 조건에 맞는 공고 N** + "마포구 대상 · 문화/행사 · 접수 중"
   - **함께 살펴볼 주변 지역 공고** + "마포구 주변 · 문화/행사 · 거주 조건을 꼭 확인하세요" (조건 충족 시에만)
   - **서울·전국 대상 공고** + "문화/행사 · 연령·거주 등 참여 조건은 상세에서 확인하세요", 카드마다 `서울 전체`/`전국` 라벨. 지역 범위만 확인된 것이므로 "신청할 수 있는" 같은 자격 표현을 쓰지 않음
- 각 묶음은 **공고가 없으면 제목·설명까지 통째로 숨깁니다.** 시안의 회색 자리 카드는 구현하지 않습니다.
- 확장 묶음에도 선택한 분야를 유지. 같은 분야라는 이유만으로 넣지 않고, 신청 대상·참여 조건(연령·거주 등)이 확인되면 맞지 않는 공고는 제외

## 3-2. 신청 핵심 정보 운영 기준

화면을 바꿔도 신청 대상·신청 방법·접수 기간이 비어 있으면 상세 화면의 효용이 떨어집니다. 화면 작업과 별개로 다음을 함께 진행합니다(데이터 파이프라인 작업은 재방문 지시서·지역 정리와 같은 브랜치 원칙을 따름).

- **우선 확보 필드**: 접수 기간(시작·마감·마감 유형), 신청 대상, 신청 방법, 신청 링크(apply_url)
- 현재 공고 중 각 필드가 비어 있는 비율을 집계해 보고(출처별)
- 비어 있는 공고는 운영 콘솔의 **검수 대기열**에 올려 사람이 원문을 보고 채울 수 있게 함
- `apply_url`은 원문에서 실제 신청 폼으로 확인된 경우에만 저장. 기관 홈페이지 주소를 신청 링크로 넣지 않음
- 화면 표시: 값이 없으면 "원문에서 확인해 주세요 · 원문 보기", 주 버튼은 `공식 공고 확인하기`

## 3-4. 화면 기획 v1.0 반영 (2026-11-01)

기준 문서는 `docs/design/PosterLink_Screen_Plan_v1.pdf`(화면 기획 v1.0)이다. 앞 장과 겹치는 부분은 이 장이 우선한다. 반영 순서는 A → B → C·D → E이며, A~D는 2026-11-01 브랜치 `feat/screen-plan-v1-20261101`에 반영했다. 운영 DB는 바꾸지 않았다.

### A. 공고 품질과 상태 (기획 09)

- **운영 종료**: 확정된 접수 마감일이 앞에 남아 있지 않은데 운영 종료일(`event_end_at`, Asia/Seoul)이 지났으면 접수 중이 아니다. 화면 표시는 "접수 종료"이고, 홈 추천과 접수 중 목록에서 뺀다. 같은 규칙을 DB 검색 함수에 넣는 마이그레이션은 `20261102010000`이며, 아직 적용하지 않았다.
- **상시·소진 시 마감**: 원문에 상시·수시·연중 또는 소진·선착순·정원 마감 문구가 있을 때만 유지한다. 근거가 없으면 원문을 다시 읽고, 대개 미확인이 된다. 미확인 공고는 "마감일은 원문에서 확인"으로 표시하고 기본 접수 중 목록에서 뺀다.
- **대상·인원**: "참가인원: 서울시민 20명"처럼 라벨이 붙은 줄이 있으면 대상과 인원 필드에 반영한다. 추정하지 않는다.
- **기존 데이터**: `scripts/crawler/src/plan-deadline-fact-backfill.js`로 dry-run만 했다. `--apply`는 승인 후 실행한다.

### B. 분류 (기획 05)

- 관심 분야는 7개 대분류와 기타다: 지원금/복지, 교육/취업, 문화/행사, 주거/금융, 소상공인, 육아/가족, 건강/의료, 기타. 관심 선택, 온보딩, 계정 수정, 찾기 필터에는 이 분류만 보인다.
- 공고 유형은 대분류에 연결해서 찾는다. 연결표는 `apps/web/lib/categoryTaxonomy.ts` 한 곳에 둔다.

### C·D. 홈과 카드 (기획 02·03·04)

- **상단**: 제목, 조건 한 줄과 "조건 변경", 검색창을 둔다. 관심 분야가 둘 이상이면 분야 칩을 둔다. 큰 안내 상자는 두지 않는다.

- **오른쪽 칸** (1200px 이상, 좁으면 아래로 내려간다): 7일 이내 마감 공고 최대 4개를 보여 준다. 화면에 이미 나온 공고는 빼서 같은 공고가 반복되지 않게 한다. 그 아래에 구독 기관 소식을 두고, 구독이 없으면 기관 둘러보기 링크를 둔다.

## 4. 문구 규칙

- **개발 설명은 화면에 넣지 않습니다.** 예: "인접 구 매핑 기준", "~일 때만 보여줍니다", "없으면 섹션을 숨겨요", "관련성이 낮은 공고는 채우지 않아요" 등은 코드 규칙으로만 둡니다.
- 확인되지 않은 표현 금지: "3초 가입" 등
- 마감 묶음은 "7일 안에 마감"(오늘 포함 7일)으로 통일. "이번 주"라는 표현을 쓰지 않음
- 지역 범위만 확인된 공고에 "신청할 수 있는" 같은 자격 표현을 쓰지 않음
- 지난 날짜에 "예정" 금지. 원문에 적힌 일정은 "공고에 적힌 ○○"으로 출처를 밝힘
- 신청 표시는 "내가 직접 표시한 기록"임을 알림
- 비회원에게 제공하지 않는 기능을 가입 혜택으로만 말하고, 비회원에게 이미 주는 기능을 가입 혜택으로 내세우지 않음

## 5. 접근성

- 버튼은 `<button>`, 이동은 `<a href>`. div·span에 클릭 핸들러 금지
- 아이콘만 있는 버튼에 `aria-label` (뒤로 가기, 공유하기, 안내 닫기 등)
- 토글은 `aria-pressed`, 탭은 `role="tablist"`/`role="tab"`/`aria-selected`, 현재 하단 탭 `aria-current="page"`
- 토스트 `role="status"`, 바텀시트 `role="dialog"` + 제목 연결 + 포커스 가두기·ESC 닫기
- 화면 확대 허용(`maximum-scale=1` 제거 — 1차 점검에서 지적된 사항)
- 장식 아이콘 `aria-hidden="true"`
- 검색 입력창: 화면에 안 보이는 라벨은 표준 visually-hidden 패턴으로 처리하고, 입력창 최소 폭 240px. 좁은 화면에서 입력창이 줄어들거나 줄바꿈되지 않는지 확인

- [ ] 비회원 찜 → 토스트 → 바텀시트 → 가입 → 원래 화면 복귀 + 찜 완료 (재방문 지시서 2단계와 함께)
- [ ] 종료 공고: 원래 공고 → 종료 안내·대안 → 내 기록 → 정보 순서, 신청 버튼 없음, "예정" 문구 없음

### 2단계: 내 공고 (⑨⑩)
- [ ] 비회원/회원 화면 분리, 가입 직후 합치기 안내
- [ ] 찜 탭 접수 상태별 묶음, 빈 묶음 숨김
- [ ] 신청 표시 전/후/취소, 표시 직후 알림 끄기 질문
- [ ] 알림 켜짐 표시는 권한 확인 후에만

### 3단계: 홈·찾기 (⑥⑦⑧⑪)
- [ ] 홈 세 상태가 조건대로 전환 (첫 방문 / 새 공고 있음 / 없음)
- [ ] 지난 방문 기준 유지 (방문 중 새로고침·뒤로 가기 후에도 같은 목록)
- [ ] 빈 섹션 숨김, 찜·구독 없는 회원은 안내 카드 하나
- [ ] 찾기 결과 세 묶음 분리, 확장 묶음에 라벨·분야 표시

### 4단계: 관심 조건 선택 (⑤)
- [ ] 앱 첫 실행에만 표시, 공유·검색 진입 시 표시 안 함
- [ ] 비회원 선택 → 가입 후 그대로 이어받음

### PC 배치 (각 단계에 함께 적용)
- [ ] 1280px에서 상세 2단(오른쪽 포스터·행동 상자 고정), 홈 2단, 찾기 사이드바 구조
- [ ] 1024px·768px에서 열이 아래로 내려가 모바일 정보 순서와 같아짐, 가로 스크롤 없음
- [ ] PC에서 하단 탭·하단 고정 바·떠 있는 제보 버튼이 보이지 않음
- [ ] PC 내 공고 화면과 상단 계정 메뉴(마이 ▾)가 모든 PC 화면에서 같은 위치·항목

### 로그인 수단
- [ ] 웹·안드로이드: 카카오·네이버, iOS 앱: 카카오·네이버·Apple 버튼 노출
- [ ] 모든 수단에서 원래 화면 복귀, 하려던 행동 완료, 비회원 찜 합치기가 동일하게 동작 (수단별 E2E 각 1건)

### 전체 흐름 E2E (모바일 뷰포트)
공고 열기 → 비회원 찜 → 토스트 → 바텀시트 "나중에" → 내 공고(비회원)에서 찜 확인 → 카카오 또는 네이버 로그인 → 내 공고(회원)에서 찜 유지 + 합치기 안내 → 홈 → 지난 방문 이후 새 공고 표시
