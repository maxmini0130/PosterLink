## 실행·복구 절차

실행 도구는 `scripts/crawler/src/apply-direct-review-20261027.js`다. `scripts/crawler`에서 다음 명령을 사용한다.

```bash
node src/apply-direct-review-20261027.js
node src/apply-direct-review-20261027.js --apply --confirm=SOURCE_REVIEW_20261027
```

첫 명령은 GET 이외의 DB 요청을 차단하는 dry-run이다. 두 번째 명령은 이번 사용자 수정 요청 범위의 6건에 한해서만 사용한다. 운영 반영 전 대상·상태·원본 스냅샷·링크·지역을 대조한다. 쓰기 중에는 검수대기로 숨기고 `updated_at` 조건으로 동시 변경을 막는다. 링크는 기존 행을 수정하거나 필요한 경로만 추가하며, 카테고리·이미지·사용자 상호작용은 수정하지 않는다. 전국 참여 정정과 홈페이지 잡음 제거를 위해 백업한 지역 연결 3개만 교체·제거한다.

원문 HTML, 첨부 포스터, 계획, 전체 원본 및 지역 연결 백업, 단계별 결과와 재조회 스냅샷은 Git에서 제외된 `data/results/manual-review-20261027/`에 보관한다. 원래 검수 메타데이터와 본문은 새 검수 근거 안에도 보존한다. 재실행은 갱신된 스냅샷과 맞지 않아 중단된다.

복구가 필요하면 `backup.json`, `poster_regions-before.json`, `applied.json`, `after-*.json`을 대조하고 이후 변경을 확인한 후 이번 수정 열·링크만 원복한다. 새로 추가한 링크는 이번 실행에서 추가된 행만 구분하며, 기존 공고나 사용자 데이터를 삭제하지 않는다. 중간 실패 시 `phase`와 `directReviewWriteInProgress`를 확인하고 검수대기를 유지한다. 복구 쓰기는 별도 사용자 승인 후 수행한다. 새 마이그레이션이나 배포는 필요하지 않다.

## 반영 결과

2026-10-27 11:13 KST 운영 반영 후 6건 모두 재조회 비교를 통과했다. 원래 보류 5건 중 2건은 AI 검토 승인, 1건은 중복 반려, 2건은 보류 유지다. 별도로 기존 공개 부부상담 1건의 접수마감을 수정하고 마감 처리했다.

익명 공개 검색에서도 새 승인 2건이 표시되고 마감한 기존 부부상담은 모집중 검색에서 제외되는 것을 확인했다. 공개 검색과 공개 집계는 모두 281건으로 일치하며, 전체 검수대기는 2건이다.

첫 반영에서 `verification_status=verified`가 관리자 전용 사람 검수 완료 표시임을 DB 트리거가 확인해 거부했다. 이 값은 이번 자동 원문 검토 범위를 넘어선 표시였으므로 계획을 `needs_review` 및 `verified_at=null`로 정정했다. 게시 승인과 사람 검수 완료는 별개이며, 관리자 계정이나 사람 검수 증거를 위조하지 않았다. 기존 DB 보호 규칙은 변경하지 않았다.

이때 첫 항목은 검수대기 잠금과 링크 변경까지만 진행됐고, 이후 최종 수정은 저장됐으나 관계 검증에서 조인 테이블에 `id` 열이 없다는 오류가 있었다. 정렬 기준을 실제 관계 키로 고쳤다. 제한된 `--resume` 경로는 최초 대상·기록된 단계·기존 필드·최종 링크가 정확히 일치할 때만 해당 항목을 이어서 처리하며, 이미 저장된 최종 변경은 재적용하지 않는다. 복구 후 모든 항목의 값·날짜·링크·이미지·카테고리와 변경한 지역 연결을 검증했고 진행 중 표시는 남지 않았다.

`applied.json`의 `verified: true`는 쓰기 결과의 재조회 일치를 뜻하며 사람 검수 완료 상태가 아니다. 크롤러 테스트 381개, 스크립트 구문 검사, Prettier, diff 검사를 통과했다. 웹 코드 변경이 없어 웹 lint/build와 화면 검증은 실행하지 않았다. 운영 데이터만 반영했으며 코드 배포·마이그레이션은 실행하지 않았다.
